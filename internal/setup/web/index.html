Set up Shepherd

Shepherd writes its own configuration from what you choose here, starts on it, and then proves it is working before you point anything at it. Nothing is written until you press Finish.

Reading this host…

1. Where Shepherd keeps its state

The portal token, your rules, the device registry and the cached blocklists go here, beside the configuration file. This is the directory to back up.

2. Which addresses should answer DNS?

Pick every address a device or your router might be pointed at. All of them is the safe answer: a device asks one specific address, so if your router hands out the wired address while Shepherd listens only on the Wi-Fi one, that device has no DNS at all and nothing in the configuration looks wrong.

Shepherd also answers on 127.0.0.1 and [::1] by itself, so this host can always resolve even if an interface goes down.

3. Which resolvers should Shepherd ask?

Shepherd filters, it does not resolve: whatever it does not block, it asks one of these. Rather than make you guess, setup asks each one the same question a few times from this host and shows what came back — encrypted resolvers that block known-malicious names are preferred, but only when they answer reliably and quickly from here.

4. What should be blocked for the whole network?

Shepherd already starts with its recommended blocklists on. These are categories on top of that, applied to every device; you can change all of it in the portal afterwards, per device or per group, and this is only the starting point.

5. Where should the portal listen?

The portal is Shepherd's own interface. It is locked behind a token and shows demo data until you sign in, but a LAN address still means anyone on the network can reach the sign-in page. Loopback plus an SSH tunnel is the private answer; a LAN address is the convenient one.

Everything not asked about keeps its default, and shepherd.example.toml documents the rest. For the state of the host itself — which ports are held, whether IPv6 works, link speeds — run scripts/shepherd-doctor; it changes nothing.

Open the portal

Point your network at Shepherd

Until you do this, Shepherd sees nothing: devices keep asking whatever resolver they were given. Do it in one of these two places.

  1. Your router's DHCP settings — set the DNS server it hands out to , then reconnect a device (or wait out its lease) and come back to the check above. This covers every device at once.
  2. One device first, if you would rather try it small: set its DNS server to the same address by hand, confirm it still browses normally, then move the router over.

Give the Shepherd host a fixed address while you are in there — a DHCP reservation for is enough. If its address moves, every device is pointed at nothing.

Shepherd can also hand out the leases itself instead of your router (DHCP mode, docs/DHCP.md). It is off, and it stays off until you turn it on in the portal: it means turning your router's DHCP server off, which is not a thing to do from a setup page before anything has been proven to work.

Per-device bandwidth (optional)

Shepherd can ask your router how much each device has moved, which is how the Bandwidth screen gets real numbers without touching any traffic. Skipping this changes nothing else.
