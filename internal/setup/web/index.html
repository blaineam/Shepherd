Set up Shepherd

Five answers and Shepherd writes its own configuration, then starts on it. Nothing is written until you press Finish, and you can come back to all of this in the portal afterwards.

Reading this host…

1. Where should Shepherd keep its state?

The portal token, your rules, the device registry and the cached blocklists go here. This is the directory to back up.

2. Which addresses should answer DNS?

Pick every address a device or your router might be pointed at. All of them is the safe answer: a device asks one specific address, so if your router hands out the wired address while Shepherd listens only on the Wi-Fi one, that device has no DNS at all and nothing in the configuration looks wrong.

Shepherd also answers on 127.0.0.1 and [::1] by itself, so this host can always resolve even if an interface goes down.

3. Which resolvers should Shepherd ask?

Shepherd filters, it does not resolve: whatever it does not block, it asks one of these. They see every name this network looks up, so this is a privacy decision as much as a technical one. Each one is tested from this host before it is written.

4. Where should the portal listen?

The portal is Shepherd's own interface. It is locked behind a token and shows demo data until you sign in, but a LAN address still means anyone on the network can reach the sign-in page. Loopback plus an SSH tunnel is the private answer; a LAN address is the convenient one.

5. Read per-device bandwidth from your router? optional

Shepherd can ask your router how much each device has moved, which is how the Bandwidth screen gets real numbers without touching any traffic. Skipping this changes nothing else, and you can connect a router later from the portal.

The password is kept in your data directory's secrets.json (0600), never in shepherd.toml.

eero signs in with a code it emails you while you wait, so that one is done from the portal's Bandwidth screen after Shepherd starts.

Everything not asked about keeps its default, and shepherd.example.toml documents the rest. For the state of the host itself — which ports are held, whether IPv6 works, link speeds — run scripts/shepherd-doctor; it changes nothing.
